## Known troubles (silent-corruption landmines — full registry: design spec §12)

These do **not** fail loud — they quietly corrupt the output, so they live here
in always-loaded context. The conventions that *do* fail loud (fail-loud
contract, scripts-as-modules, `pythonpath = .`, typing) live in
[coding-standards.md](docs/coding-standards.md) and
[testing-guide.md](docs/testing-guide.md).

- ffmpeg seek: `-ss` **after** `-i` for frame-accurate cuts (the black-frames
  landmine was arg order, not 4K).
- `lutrgb` is **banned** (black frames) — `colorchannelmixer` only.
- Never stabilize wade-in/out shots ("rolling ground"). **No machine predicate
  exists** — the flag is explicit by design, and auto-enabling on measured shake
  would fire hardest on exactly this shot (2026-07-20 §7).
- `zoompan` needs explicit `s=`/`fps=`/`d=` — the defaults (hd720 / 25fps /
  90-frame hold) silently resize, resample and stall. And it clamps `z` below 1
  to 1 **byte-identically**, so a pull-out expressed as a shrink renders nothing.
- `setpts` remaps timestamps but does **not** resample — without a following
  `fps=` the output is VFR and concat's uniformity check rejects it. And a
  filtergraph value containing a comma must be single-quoted *inside* the `-vf`
  string: in argv form nothing strips shell quotes, so the first bare comma
  splits the filter chain.
- `blend=all_mode=multiply` against a single-plane (grayscale) mask destroys
  **chroma**, not just luma — U/V sit at 128 for neutral, so the multiply drags
  them toward 0 (measured mean |ΔU| 63.44). Use `overlay` through alpha, or
  restrict the blend to the luma plane. **Machine-checked**: the landmine
  lint's sixth `check_argv` check refuses it outright (2026-08-13 §8.1).
- Converting an encode's colour range takes **`-pix_fmt yuv420p` AND at least one
  of** `-color_range tv` / `scale=in_range=auto:out_range=tv`. Measured 2026-08-27
  over all seven combinations on a real `pc` source: **without `-pix_fmt yuv420p`
  nothing converts** — filter alone, tag alone and both together all come back
  `yuvj420p`/`pc`, byte-identical — and `-pix_fmt yuv420p` **alone** does not
  convert either. With it, filter alone, tag alone and both are byte-identical and
  all convert. So `-pix_fmt` is individually necessary and not sufficient; the
  pair is sufficient given it, and either half will do. `extract` carries all
  three because it costs nothing, but the redundancy inside the pair means no
  check over rendered pixels can notice one half going missing — the argv-level
  test is the only guard there. And `TV_LO`/`TV_SPAN` are constants of **bit
  depth** as well as range: a 10-bit plane through the same LUT comes back with
  99% of its pixels on one code.
- `select` placed **before** a chain's `fps=` emits the SAME frame once per
  requested frame: `fps` re-interpolates the dropped frames back up to rate by
  duplicating the survivor, and the output frame count is still right, so nothing
  fails. Measured 2026-08-15: three requested frames came back as one frame three
  times. Append a sink filter at the END —
  `reframe.RenderPlan.with_tail` does. **Machine-checked**: the landmine lint's
  seventh `check_argv` check.
