# cap-3 Parallel Episode Fan-out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Turn `edl_to_reel`'s sequential per-episode `process_episode` loop into a bounded thread pool (default 3), closing stage §5.1's last open sub-item.

**Architecture:** A `ThreadPoolExecutor(max_workers=jobs)` replaces the `for` loop. Every future is joined by the `with` block, then results are read **in index order**, so both failure channels (a returned status, a raised exception) report the lowest index and never depend on thread scheduling. A `track.ensure_model` preflight materializes the YOLO weights once before any worker starts — without it, N cold workers race to write one weights file.

**Tech Stack:** Python 3.13 stdlib `concurrent.futures` + `threading`; pytest with `threading.Barrier` for deterministic concurrency assertions; ultralytics faked via `sys.modules` (never downloaded in the suite).

**Design spec:** [`docs/specs/2026-07-18-cap3-fanout-design.md`](../specs/2026-07-18-cap3-fanout-design.md) — read §2 (the measurement), §4 (failure semantics) and §5 (the weights race) before Task 3.

```python
def _six(tmp_path):
    """Six episodes — divisible by 3, so a jobs=3 pool fills exactly twice with no
    ragged tail. Fewer than 6 would let a lucky schedule fake the concurrency."""
    ep = dict(source="a.mp4", dur=2.0, shot_type="wide",
              composition="lead", grid="thirds", crop_scale=0.8)
    return _edl_file(tmp_path, episodes=[{**ep, "start": float(i) * 2.0} for i in range(6)])


def test_the_pool_reaches_the_cap_and_never_exceeds_it(monkeypatch, tmp_path):
    # One fake proves both halves. The barrier forces `jobs` workers to be inside
    # fake_pe simultaneously: a sequential driver never assembles 3 parties, so
    # barrier.wait() times out and raises BrokenBarrierError. Because the barrier
    # HOLDS all three, peak == jobs is forced rather than hoped for — a bare counter
    # could observe 2 on an unlucky schedule and flake.
    jobs = 3
    barrier = threading.Barrier(jobs, timeout=10)     # deadlock backstop, not a timing assumption
    lock = threading.Lock()
    state = {"live": 0, "peak": 0}

    def fake_pe(manifest, project_dir, route_path=None, color_correct=None):
        with lock:
            state["live"] += 1
            state["peak"] = max(state["peak"], state["live"])
        barrier.wait()
        with lock:
            state["live"] -= 1
        return {"status": "mechanical_pass", "clip": manifest["out_path"]}

    _wire(monkeypatch)
    monkeypatch.setattr(edl_to_reel.process_episode, "process_episode", fake_pe)
    res = edl_to_reel.edl_to_reel(_six(tmp_path), _project(tmp_path), str(tmp_path),
                                  str(tmp_path / "w"), str(tmp_path / "out"), jobs=jobs)
    assert res["status"] == "delivered"
    assert state["peak"] == jobs


def test_every_episode_gets_its_own_scratch_and_output(monkeypatch, tmp_path):
    # The load-bearing precondition for parallelising at all: process_episode's
    # docstring warns that a shared project_dir clobbers a sibling's route/path/
    # report. Pin it rather than trust the comment.

    edl_to_reel.edl_to_reel(_six(tmp_path), _project(tmp_path), str(tmp_path),
                            str(tmp_path / "w"), str(tmp_path / "out"), jobs=3)
    dirs = [m["project_dir"] for m in seen["pe"]]
    outs = [m["manifest"]["out_path"] for m in seen["pe"]]
    assert len(set(dirs)) == 6 and len(set(outs)) == 6
    assert sorted(Path(d).name for d in dirs) == [f"ep{i}" for i in range(6)]


def test_every_episode_runs_even_after_an_earlier_one_fails(monkeypatch, tmp_path):

    # would otherwise cause, and preflight built both paths per index.

        track.ensure_model(model)      # before ANY worker: N cold workers would race the
                                       # same weights download into the same path (§5)
    with ThreadPoolExecutor(max_workers=jobs) as ex:
        futures = [ex.submit(process_episode.process_episode, md,
                             str(Path(work_dir) / f"ep{i}"))   # md already resolved → no project=
                   for i, md in enumerate(mds)]
    # the `with` block joined every worker, so each future below is already done and this
    # ONE loop reads them in index order — no dependence on completion order anywhere.
    #
    # One pass, not two. An episode can fail through either channel (a raised setup error
    # or a returned non-pass status), and the two must be ordered AGAINST EACH OTHER, not
    # each within itself: draining every exception first would let a raise at episode 2
    # beat a routable stop_and_report at episode 0 — which the sequential loop returned
    # before it ever reached episode 2. Whichever problem sits at the lowest index wins,
    # whatever kind it is; that is what makes the finding identical to the sequential one.
    episodes: list[ReelEpisode] = []
    for i, (md, fut) in enumerate(zip(mds, futures, strict=True)):
        try:
            res = fut.result()
        except Exception as e:         # a hard setup error stays an exception, per the docstring
            e.add_note(f"raised while processing episode {i} (segment {md['segment']})")
            raise
        if res.get("status") != "mechanical_pass":
            return {"status": "stop_and_report",
                    "finding": {"reason": "episode-failed", "episode_idx": i,
                                "sub_status": res.get("status")}, "sub": res}
        epdir = str(Path(work_dir) / f"ep{i}")
        episodes.append(ReelEpisode(manifest=md, clip=res["clip"],
                                    route=str(Path(epdir) / "route.json"),
                                    path=str(Path(epdir) / "path.json"),
                                    meta=str(Path(epdir) / "path.meta.json")))
```

`zip(..., strict=True)` pins `len(futures) == len(mds)`. With the single loop that
equality is a structural invariant of the comprehension one statement above, so
the guard cannot fire today — it is a cheap assertion that the pairing stays
one-per-episode if anyone ever filters or batches the submits, where a silent
`zip` truncation would assemble a reel from fewer episodes than were planned.

Finally, update the module docstring's first paragraph — it currently calls the loop SEQUENTIAL and calls the parallel fan-out "a later optimization":
