# fit-solid Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the background filler a real parameter — `solid` joins `blur` — and rename the mode `fit-blur` → `fit` so the mode names a geometry and nothing else.

**Architecture:** The layouts model already treats a layout as crop × rect × filler, and `background` already rides from the manifest all the way to `ResolvedLayout`. This slice widens the filler vocabulary, gives it a colour, teaches `reframe._filter_args` a second background producer (a synthesized `color` source instead of a blurred copy of the input), records the filler in the `path.meta.json` sidecar, and renames the mode whose name had swallowed the filler.

**Tech Stack:** Python 3.13, ffmpeg (`color` source, `overlay`, `boxblur`), pytest.

**Design:** [`docs/specs/2026-07-18-fit-solid-design.md`](../specs/2026-07-18-fit-solid-design.md)

**Baseline before Task 0:** `1259 passed, 8 skipped`.

**Run the suite with:** `.venv/bin/python -m pytest -q ; echo "EXIT: $?"` — never pipe it through `tail`.

**Test-strength rule (this slice has already been bitten twice):** when a test is
the only thing reading an error message, pin the part that carries the
information — the offending value and the enumeration of what *is* accepted — not
a single word from it. `match="unknown"` survives the message being erased down
to the bare word; `match=r"background 'x' unknown"` plus an assertion on the
enumeration does not. The same applies to a substring that is a prefix of the
string it replaced: `"fit" in p` passes against `"fit-blur"` too. Both of these
shipped in this slice's first two tasks and both were caught by mutation, not by
the suite going red.

### Task 4b: bound the `color` source with `d=`, and give `proc.run` a timeout

**Amendment, added after Task 4's review measured what `shortest=1` actually
does.** Design §4 now carries the full account; the short version:

- `overlay=…:shortest=1` terminates, but lands **exactly one frame short of the
  source, every render, at any frame rate** (golden fixture: source 95 frames,
  blur 95, solid 94; reproduced on 1s/3s/5s synthetics). `eof_action=endall` is
  identical — the truncation is inherent to ending an overlay against an infinite
  source.
- One frame accumulates into a real gate: `check_reel` measures the assembled
  reel against `_LENGTH_TOL` (0.5s), so ~30 solid episodes at 59.94fps eat the
  whole band, and `length_retime_max` on top. **A filler must not change how long
  the reel is.**
- `proc.run` has no `timeout`, so the unbounded case hangs the suite instead of
  failing it (measured: 90s and killed, against a 0.8s normal run). There is no
  `timeout`/`gtimeout` binary on this machine to bound it from outside.

**Files:** `scripts/reframe.py`, `scripts/lib/proc.py`; tests in
`tests/integration/test_reframe.py`, `tests/lib/test_proc.py`.

- [x] **Step 1: `_probe` also returns duration.** It already runs `ffprobe`; add
  `duration` to the `-show_entries` and return it — no extra process. A source

  existing `fps <= 0` raise beside it. Do **not** fall back to `shortest=1`: that
  would reintroduce the truncation invisibly on exactly the files nobody checked.

- [x] **Step 2: thread `dur` into the filtergraph.** `_background_args(rl, fps,

def _background_args(rl: ResolvedLayout, fps: float) -> tuple[str, str, str]:
    """(bg_chain, fg_source_label, overlay_opts) for one filler.

    blur reads the source TWICE — a scaled cover for the background and the
    tracked crop for the content — which is the only reason the composite
    splits. solid SYNTHESIZES its background and reads the source once, so it
    does not split. The difference in shape is caused by the filler, which is
    what makes this a parameter and not a branch: both arms hand back a [bg], a
    [fg] and one overlay, over the identical tail.
    """
    if rl.background == "solid":
        # `color` is an INFINITE source. Without shortest=1 the overlay never
        # sees end-of-stream on either input and the encode does not terminate
        # (design §4) — it is not a tidiness flag, it is what makes ffmpeg stop.
        return (f"color=c={rl.background_color}:s={rl.out_w}x{rl.out_h}:r={fps:.6g}[bg];",
                "[0:v]", ":shortest=1")
    # boxblur rejects a radius at/above half the chroma plane; yuv420p halves the
    # plane again, so the ceiling is the largest radius STRICTLY under
    # min(out_w, out_h) / 4 — i.e. (min(out_w, out_h) - 1) // 4. ffmpeg 8.1.2
    # tightened this bound to a strict `<` (8.1.1 accepted radius == min/4), so a
    # 3840x200 cover now refuses 50 and survives at 49; a 1280x4 cover refuses 1
    # and survives at 0.
    #
    # The ceiling is applied LAST. Written as max(2, min(w // 60, ceiling)) the
    # floor wins whenever the ceiling is 0 or 1 — a canvas under 8px on its short
    # side would ask for radius 2 and ffmpeg would refuse it, which is the very
    # crash the ceiling exists to prevent. Below 8px the blur is meaningless
    # anyway; radius 0 is a legal no-op.
    radius = min(max(2, rl.out_w // 60), (min(rl.out_w, rl.out_h) - 1) // 4)
    return (f"[0:v]split=2[a][b];"
            f"[a]scale={rl.out_w}:{rl.out_h}:force_original_aspect_ratio=increase,"
            f"crop={rl.out_w}:{rl.out_h},boxblur={radius}:2[bg];",
            "[b]", "")

def _duration(path):
    out = subprocess.run(
        ["ffprobe", "-v", "error", "-show_entries", "format=duration",
         "-of", "json", str(path)],
        capture_output=True, text=True, check=True)
    return float(json.loads(out.stdout)["format"]["duration"])


def _pixel(path, x, y):
    """RGB of one pixel of the first frame — crop to 1x1, dump raw rgb24.

    `:exact=1` is load-bearing on ffmpeg 8.1.2, found while implementing this
    task: without it, `crop` rounds a 1x1 request down to the chroma-
    subsampling boundary (yuv420p halves both planes) and refuses outright —
    `Invalid too big or non positive size for width '0' or height '0'`, exit
    234 — rather than silently returning a bigger crop. `exact=1` disables
    that rounding so an odd, non-chroma-aligned 1x1 request is honoured
    literally.
    """
    out = subprocess.run(
        ["ffmpeg", "-v", "error", "-i", str(path), "-vf", f"crop=1:1:{x}:{y}:exact=1",
         "-frames:v", "1", "-f", "rawvideo", "-pix_fmt", "rgb24", "-"],
        capture_output=True, check=True)
    return tuple(out.stdout[:3])

>   accident. (`reframe._background_args`, fit-solid 2026-07-18.)

>   the same injection surface as `border_color` and gets the same guard against
